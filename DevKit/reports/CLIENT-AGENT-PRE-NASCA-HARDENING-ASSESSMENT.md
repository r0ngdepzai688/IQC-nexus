## Phase 2D Inspection Matrix (Payload Idempotency & Replay Protection)

| # | Inspection Item | Classification | Inspection Findings & Analysis |
| :- | :--- | :--- | :--- |
| 1 | **Nonce Generation** | **DTO DEFAULT** | Nonce had a default `Guid.NewGuid().ToString("N")` property initializer in the request DTO rather than requiring client generation. |
| 2 | **Nonce Persistence** | **MISSING** | Nonce was not stored in the client local SQLite queue or the server database. |
| 3 | **Nonce Uniqueness** | **MISSING** | No database unique index or check existed for nonces. |
| 4 | **Nonce / Device Binding** | **MISSING** | Nonces were not bound cryptographically to `AgentDeviceId` and `PayloadSubmissionId`. |
| 5 | **Source Fingerprint Generation** | **INSUFFICIENT** | Fingerprint was computed ad-hoc without a strict canonical representation of the normalized workbook content. |
| 6 | **Canonical Payload Hashing** | **MISSING** | Server did not recompute or verify SHA-256 canonical digests over the payload. |
| 7 | **Duplicate Submission Handling** | **MISSING** | The server accepted duplicate submissions without detecting idempotency or returning committed references. |
| 8 | **Concurrent Duplicate Handling** | **SECURITY RISK** | Parallel duplicate uploads created multiple independent accepted upload IDs. |
| 9 | **Lost-Response Recovery** | **MISSING** | Network transport loss left the client unable to retrieve the committed upload ID upon retry. |
| 10 | **Cross-Device Replay Prevention** | **PARTIAL** | Validated device existence, but lacked unique submission binding across devices. |
| 11 | **Payload Ownership Validation** | **VERIFIED** | Authenticated device ID verified against active agent devices. |
| 12 | **Retention & Cleanup** | **MISSING** | No persistent submission history or retention policy existed. |

## Required Architectural Design for Phase 2D

1. **Submission Identity**: Introduce `PayloadSubmissionId` (`agt_sub_<guid>`), generated by the Agent once per logical submission, persisted in SQLite local queue.
2. **Canonical Payload Hash**: Server recomputes SHA-256 digest over invariant UTF-8 canonical JSON binding `(SchemaVersion, NormalizedWorkbook, SourceFingerprint, Nonce, PayloadSubmissionId, DeviceId)`.
3. **Database Uniqueness**: Create `AgentPayloadSubmission` table with unique indexes on `(AgentDeviceId, PayloadSubmissionId)` and `(AgentDeviceId, Nonce)`.
4. **Atomic Acceptance & Idempotency**: Single database transaction commits payload submission. Retry with same `PayloadSubmissionId` and `Nonce` returns the exact original `UploadId` with `IsDuplicateRetry = true`.
5. **Replay & Collision Protection**: Mismatched payload or cross-device attempt fails closed.
